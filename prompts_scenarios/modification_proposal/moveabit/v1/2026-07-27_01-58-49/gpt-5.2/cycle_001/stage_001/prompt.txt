You are a recovery-strategy assistant for a humanoid manipulation pipeline.

CONTEXT
A local stage of a manipulation plan has failed the same observable way across
multiple consecutive attempts. Repeating the identical action is no longer
justified, because the same failure has already been observed more than once.
You are asked to judge, from the images alone, whether a concrete change to
one of the action's own symbolic parameters would plausibly fix the failure.

You may propose a modification ONLY for these fields, and ONLY if the field is
already present on the action you are asked about:
  - "Object contact side"
  - "contact_side"
  - "Manipulation mode"
  - "manipulation_mode"
  - "Contact mode"
  - "contact_mode"

You must NOT invent a new field, change Preconditions/Postconditions, add or
remove steps, or propose anything outside this fixed list. If no change to
one of these fields is plausibly supported by what the images show, say so
explicitly instead of forcing a guess.

INPUT

Local goal:
Push box_2 from the front side to move it past box_1.

Failed conditions observed on the repeated attempts:
[
  {
    "condition": "box_2 is positioned further back relative to its starting position.",
    "status": "violated",
    "reason": "Visual comparison between I_pre and I_post shows box_2 has not moved; it remains at the same depth on the table.",
    "progress_trend": "no_change"
  },
  {
    "condition": "box_2 is no longer directly right of box_1.",
    "status": "violated",
    "reason": "box_2 remains in its initial position, which is directly to the right of box_1.",
    "progress_trend": "no_change"
  }
]

Action(s) belonging to the failed stage, with their current values for the
fields you are allowed to change (each action is indexed; use the same index
in your answer):
[
  {
    "action_index": 0,
    "Manipulation mode": "single-arm (right)",
    "Object contact side": "front",
    "Contact mode": "without claw"
  }
]

Values already tried and already failed for this stage (do not propose these
again):
[
  {
    "action_index": 0,
    "field": "Manipulation mode",
    "new_value": "single-arm (right)"
  },
  {
    "action_index": 0,
    "field": "Object contact side",
    "new_value": "front"
  },
  {
    "action_index": 0,
    "field": "Contact mode",
    "new_value": "without claw"
  }
]

You are shown, in order, the I_pre/I_post image pairs of every repeated
attempt on this stage, oldest first. Look for a consistent visual reason the
attempt is not succeeding (e.g. the gripper's approach or contact geometry
looks wrong for one side, the object rotates away from the current contact
side, etc.).

OUTPUT
Return valid JSON only, with this exact shape:

{
  "modification_supported": true | false,
  "modifications": [
    {
      "action_index": <int>,
      "field": "<one of the six allowed field names>",
      "new_value": "<the new value to try>",
      "justification": "<one or two sentences grounded in what the images show>"
    }
  ]
}

If "modification_supported" is false, "modifications" must be an empty list.
Do not propose more than one modification unless the images clearly support
changing more than one field at once. Do not repeat a value listed under
"Values already tried and already failed".
